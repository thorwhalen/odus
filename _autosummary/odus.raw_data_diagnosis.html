odus.raw_data_diagnosis¶

Diagnosis of the raw survey spreadsheets.

Reads the source .xlsx files with openpyxl (values and cell colors) and reports the data-entry anomalies that must be resolved before the data can be prepared: cells whose content and color disagree, values that aren’t 0 or 1, ages and years that don’t follow each other, repeated variables…

Each check is a Rule: a name, a function marking the problematic cells of a SheetView, and a message explaining the problem. DFLT_RULES maps names to the rules used by default; pick, drop or add rules with select_rules, or by passing any {name: Rule} mapping as rules:

>>> sorted(select_rules(exclude=['filled_but_uncolored']))
['age_not_consecutive', 'age_year_mismatch', 'duplicate_variable',
 'empty_but_colored', 'not_binary', 'year_not_consecutive']

diagnose_file and diagnose_dir yield one Problem per flagged cell, diagnosis_table puts them in a DataFrame, and print_diagnosis prints them.

Print the diagnosis of the raw xls files in source_dir.

For every file that has a problem, print its name, then for each rule that flagged something, the rule’s name and the explanation of each flagged cell.

The checks are the rules (default DFLT_RULES); see the module docstring and select_rules to turn some off or add your own. For instance, the color rules only make sense for spreadsheets where filled cells are colored.

odus.raw_data_diagnosis.select_rules(include=None, exclude=(), *, extra=None, rules=None)[source]¶

Make a {name: Rule} mapping: turn rules on or off, and add your own.

Parameters:

  • include – Names of the rules to keep (default: all of rules).

  • exclude – Names of the rules to drop.

  • extra – More rules to add: a {name: Rule} mapping or an iterable of Rule instances.

  • rules – The rules to start from (default: DFLT_RULES).

>>> list(select_rules(include=['not_binary']))
['not_binary']
>>> my_rule = Rule('never', lambda view: view.false_mask(), 'never happens')
>>> 'never' in select_rules(extra=[my_rule])
True
